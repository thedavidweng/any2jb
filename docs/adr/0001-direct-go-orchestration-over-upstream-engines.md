# Direct Go orchestration over upstream ns2jb engines

Instead of wrapping `mac2jb`'s Electron/SwiftUI orchestration scripts (`gui-host.cjs`, `gui-session.cjs`, `host-wrapper.cjs`), `any2jb` implements session orchestration, LAN binding, readiness checks, pairing-command extraction and state transitions directly in Go, invoking pinned upstream `ns2jb` Node.js engines (starting from `pepsipu/ns2jb` `engine/switch2/pipeline.cjs`) through a minimal structured bridge and reusing `mac2jb` only as a feature reference and source for standalone helpers (C USB HID senders, SaveKit and launcher integrations). This avoids carrying over `mac2jb`'s macOS-coupled wrapper layer and duplicate `host-profiles.json` copies while preserving the timing-sensitive upstream Node engines and native USB HID helpers unchanged.
