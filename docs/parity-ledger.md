# mac2jb functional parity ledger

Baseline: [cpypwn/mac2jb at ce1ce5f4f40b412cf83ba0a4f10ac53a850ed308](https://github.com/cpypwn/mac2jb/tree/ce1ce5f4f40b412cf83ba0a4f10ac53a850ed308).
Inventory includes the README's 23 headings, the Swift GUI's controls (including
dynamic homebrew choices and icon-only console controls), console-side app
actions described by the README, and the optional MCP/bootstrap-kit guides.
Repeated buttons in different panels share a capability row. Closing a dialog
without starting an operation is covered by `dialog-dismiss`.

This is the current implementation ledger, not a promise that the reference
features work in any2jb. The development shell includes About and validated
host/input preferences under Developer Options.
No console or USB behavior has been verified.

The session view binds `inspect`, `start`, `bootstrap`, `save`, `confirm-save`,
`cancel`, `stop` and `finish` only to an explicitly injected simulated environment
in [windowless UI tests](../main_test.go). These keys do not advance the rows'
dispositions or evidence: production adapters are not wired into the entrypoint.
See the [controller seam](session-controller.md) for the tested boundary.

Host profile selection, edition/capability gates and local preference reload are
covered by the [host profile tests](host-profile-ui.md#host-profile-tests).
Capability buttons do not claim working tool adapters or console verification.

The [read-only readiness adapter](readiness.md) implements local LAN selection,
independent driver facts and attached-controller discovery. The dashboard shows
the override outside Developer Options and distinguishes all three check states.
Console reachability, USB enumeration and accepted keyboard input remain not
verified. Production composition belongs to the host integration.

## Reading and maintaining the ledger

- **Tier:** `P1a` is core macOS and read-only tools; `P1b` is extended parity.
  The [release decision](adr/0002-split-phase1-release-into-p1a-and-p1b.md)
  is authoritative. Read-only OunceCake/SD export is P1a even though launchers
  and other homebrew are P1b.
- **Disposition:** `reused` means upstream code is actually integrated;
  `reimplemented` means any2jb implements the capability; `gated` means it
  is unavailable pending implementation, prerequisites, licensing or proof;
  `excluded` requires an explicit reason. A future plan to reuse is not reuse.
- **Evidence:** `not verified`, `unit-tested`, `integration-tested`,
  `hardware-verified`, or `blocked`. Evidence is independent of disposition
  and the `experimental` boolean. A drawn button is not integration evidence.
  Link the exact test/log when advancing a row. Hardware evidence must record
  platform, firmware, game, host revision, transport, date and observed result.
- **Experimental:** preserves upstream prototype/hardware-test qualifications,
  including experimental writes and switching. `false` does not establish
  hardware compatibility.
- **Risk:** `read-only`, `input`, `session`, `security`, `save-write`,
  `persistence`, `code`, `network`, `local-write`, `credentials`, or `update`.
  Network services still require explicit interface/port and access boundaries;
  read-only does not mean private exports can be logged.
- **Tickets:** local implementation ticket numbers, not external issue links.
  `backlog: deferred parity` identifies unscheduled extended scope. Gate tickets
  do not imply ownership of an entire integration.
- **UI keys:** `-` means no shipped action yet. Give each interactive MyGo control
  a literal `c.Key("action-id")` and list that key here (comma-separated when
  several controls implement the same capability). `go test ./...` checks
  common MyGo buttons, selectors, toggles and input controls across non-test Go
  files, including aliased imports. New custom widgets, application menu callbacks
  and other interaction APIs must extend `isParityControl` or receive an
  equivalent coverage check when introduced. This static check is not a runtime
  reachability or completeness proof.
- Keep 13 nonempty columns per row; use `-` for intentionally absent UI keys.
  Do not put literal table separators inside a cell.

## Shared preconditions and boundaries

`Core` means the pinned host/bootstrap/edition match, supported firmware/game,
internal game storage with enough save space, separate reachable LAN (Switch
Ethernet), and the correct console screen. `HID` means Apple Silicon macOS 14+,
informed driver setup, no pending restart, actual device-mode enumeration and
US keyboard layout, not merely a USB-C socket. `RPC` means a fresh verified run
with the selected profile's retained capability, a live lease and no competing
tool. `Backup` means explicit target/account selection, compatible game closed,
preview/confirmation and a verified original backup before changing an existing
save. These are requirements, not checks already implemented.

Never repeat REMOVE in the same game session. Inspect partial input before any
retry; uncertain side effects require console inspection/restart. Network loss
does not authorize RPC reconnection. CivSwitch's loader is not ns2jb retained RPC.
All integrations must pass ticket 04's redistribution gate before bundling;
user ROMs, game data, keys and mods are not bundled.

## Redistribution release blockers

The [redistribution assessment](redistribution.md) records supplied terms and
proposed distribution forms. It is not legal clearance. The canonical
[manifest](../manifest/profiles.json) is the only packaging allowlist.

- **P1a core release blocker:** all six host/bootstrap profiles remain blocked.
  pepsipu, kurumuz (including Astral), Cellenseres and BermTheSequel supply no
  root license at their pins; IZMYSH's scoped GPL grant does not clear inherited
  ns2jb rights. Retained notices and checksum verification are not permission.
  Their upstream acquisition URLs remain in the manifest for independent
  inspection; no download/import execution route is implemented or approved.
- **P1a read-only tools blocker:** OunceCake GPL v2-family packaging
  needs exact grant/source/build/notice review; inherited SD-browser modules
  need their own rights review. A separate subprocess is not clearance.
- **P1b launcher and integration blockers:** modloader needs its own GPL v2
  source/build/notice review; Artemis has no supplied license;
  Balatro/Gravity Circuit archives need a separate GPL v3 assessment and
  game-data review. MintBrew/GPUBrewLauncher/legacy HBLauncher, inherited IZ2S
  tools, NUP source, artwork, ROMs and shareware remain unapproved. See the
  assessment for precise source notices and alternate upstream acquisition.
- **Explicit exclusion:** the browser research probe set has no grant to
  any2jb. Another maintainer's reported permission is not transferable
  authorization. No package includes it. Future tool UI must show
  `DistributionFor("browser-research")`'s unavailable reason and leave its
  action disabled; there is no implemented Advanced Tools entry yet.
- **Packaging gate still required:** exact Node/native/runtime artifacts and
  their dependencies need manifest records and complete notices. libusbd and
  driver MIT/APSL obligations, Go transitive notices, final app inspection,
  signing and hardware acceptance are not cleared by a resource-only check.

`go test ./...` checks the source resource inventory and
`go tool mygo build` runs the fail-closed package gate. Those checks establish
exclusion/integrity, not legal permission or hardware evidence. Source-only
development is not a redistributable functional release.
## Not verified

Every row linking this note is **not verified in any2jb**: the capability is
not implemented or integrated, no authentic end-to-end result is available,
and hardware acceptance is awaiting a real rig (ticket 24). Unit tests for
ledger completeness do not advance a capability's evidence. Gated optional
tools remain visible here even if their UI or redistributable assets never ship.
Rows marked `backlog: deferred parity` need a follow-up ticket before their
implementation can be treated as scheduled.
